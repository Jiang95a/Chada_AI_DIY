## 2. 本轮必须完成

### 2.1 工具记录落库

**目标**：回看不只分析活动表单，也能分析能量牌局和三栏记录，并且跨设备可用。

必须：

1. 新增 `tool_records` 表（或等价持久化方案）：
   - `id`
   - `user_id`
   - `type`：`energy` / `thought`
   - `title`
   - `summary`
   - `tags` JSON
   - `created_at_ms`
2. 新增接口：
   - `POST /api/v1/tools/records`
   - `GET /api/v1/tools/records?days=30`
   - `DELETE /api/v1/tools/records/{id}`
3. 工具页保存时：
   - 已登录：写后端；失败再写本机
   - 未登录：只写本机
   - 本机旧记录保留读取能力
4. 聚合时：
   - `InsightFacts.events` 增加 `source: "tool"`
   - `toolRecordCount` 单独计数，不抬高 `activityCount`
5. 隐私：
   - 接口只读当前 token 的 user_id
   - 不返回其他用户记录
   - 删除只删自己的

验收：

- 登录后保存一条能量牌局，换浏览器仍能读到
- `/insights/facts` 返回 `source: "tool"` 事件
- 未登录保存不会 401 阻断本地记录

### 2.2 回看分析接口

新增：

```http
POST /api/v1/insights/analyze
Authorization: Bearer <token>
Content-Type: application/json
```

请求：

```json
{
  "days": 30,
  "allowQuote": true,
  "locale": "zh-CN"
}
```

要求：

1. 服务端自己取 `InsightFacts`，**不信任前端传的计数**。
2. 数据不足直接返回 `insufficient_data`，不调用模型。
3. 危机词先走规则，返回 `crisis`，不调用模型。
4. 调用模型 provider，要求返回严格 JSON。
5. 校验：
   - JSON Schema
   - 每条 finding 至少 1 条 evidence
   - 日期 / 活动名必须在 facts 中
   - 无诊断词、无风险评分、无绝对化人格判断
6. 失败重试一次；仍失败返回 `analysis_error`，不返回半成品。
7. 记录 `insightId`、`model`、`promptVersion`、输入哈希，便于复现。
8. 缓存同一用户 / 同一 facts 哈希 / 24 小时。

响应结构以 `docs/回看智能体-需求文档.md` 第 7 节为准。

### 2.3 模型配置

必须通过后端环境变量或配置中心读取：

```text
AI_PROVIDER=
AI_BASE_URL=
AI_API_KEY=
AI_MODEL=
AI_TIMEOUT_MS=
```

禁止：

- 把 key 写进前端
- 把 key 提交到 git
- 在日志里打印 key、用户原文

### 2.4 前端回看入口与结果

在 `/trace` 增加：

```text
[让 AI 回看这段时间]
```

必须覆盖：

| 状态 | 行为 |
|---|---|
| 未登录 | 提示登录后可跨设备回看 |
| 0 条 | 不显示可点击按钮，引导先记录 |
| 1–2 条 | 允许分析，但结果只复述，不声称模式 |
| 正常 | 显示标题、1–3 条发现、证据、变化、下一步、问题 |
| 数据不足 | 显示 `insufficient_data.message` |
| 危机 | 显示资源，不显示分析 |
| 超时 | 可重试 |
| 校验失败 | 隐藏半成品，提示重试 |

结果要求：

- 每条发现下方展示证据 chips：日期 + 活动名
- 底部说明「基于你留下的记录，不是心理评估」
- 支持复制 / 保存回看卡
- 回看卡用 SVG/HTML 生成，**不调用图片模型生成中文文字**

### 2.5 安全边界

不得：

- 诊断、风险分级、预测
- 让模型直接访问数据库
- 把表单 `answers` 送入模型
- 未经 `allowQuote` 引用原话
- 把用户原文写进应用日志
- 自动分析、定时分析、后台监控

必须：

- 危机词规则前置
- 输出过滤
- 越权测试
- 未登录 401
- 限流：每用户每分钟 2 次、每天 10 次

### 2.6 测试与评估

必须补：

1. 后端单元测试：
   - 0 / 1–2 / 3+ 条事件
   - 危机词
   - 提示词注入
   - 非法 JSON
   - 无 evidence 的 finding
   - 跨用户隔离
2. 前端测试：
   - 入口状态
   - 结果渲染
   - 错误态
   - 工具记录合并
3. fixtures 至少 10 组，见产品文档第 12.3 节。
4. 回归：
   - 现有 75 条前端测试全过
   - `vue-tsc --build`
   - `vite build`
   - 后端 `mvn test`

## 3. 不要破坏

- 不要恢复深色模式或 `data-theme="dark"`。
- 不要把摄影 / 比赛 / 志愿者等通用模板重新放回模板库。
- 不要改 `/traces` 现有契约；`history` 只增不改。
- 不要把 `/insights/facts` 改成返回表单答案。
- 不要在前端直接调用模型 API。
- 不要把回看结果直接写成诊断或建议清单。
- 不要为了“显得智能”在 1 条记录时编造模式。

---
