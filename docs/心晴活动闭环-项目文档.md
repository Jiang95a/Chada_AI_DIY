# 心屿同行 · 项目文档

> 校园心理社团活动平台。本文档整合现有前端实现与「心晴活动闭环器」需求，作为下一步开发的依据。

## 1. 一句话定位

现在的项目是「帮心理社团把活动做出来」：建项目 → 编辑页面 → 发布 → 收表单。
目标形态是「把一场活动变成一条线」：快速搭建 → 动态参与 → 匿名记录 → 回响 → 下一次接上。

## 2. 现状

### 技术栈

| 层 | 选型 |
|---|---|
| 前端 | Vue 3.5 + TypeScript + Vite 8 + Vue Router 5 + Pinia |
| 样式 | 自建 CSS 令牌，无 UI 框架 |
| 测试 | Vitest，12 个 spec |
| 后端 | Spring Boot（8080），agent 服务（8000，经后端转发） |

### 已实现

- **页面工坊**：`PageDocument` 受控组件（13 种），多页面、拖拽、撤销重做、自动保存、`auditDoc` 质检、AI 提案 → apply
- **活动运营**：项目 CRUD、草稿 revision 冲突（409）、发布、参与数据、转介、导出
- **公开活动页**：`/p/:slug`，含知情同意、活动后反馈、转介意愿、日历导出
- **容错**：本地种子数据 + 离线草稿，后端不可用时仍可编辑

### 问题

1. 所有「参与」最终收敛成一张表单提交，数据库存的是提交记录，不是人的变化
2. 编辑器文档双写（`diy-campus:doc:v1` 与项目草稿），切项目时存在串内容的窗口期
3. 后端多个接口 500（`/projects`、`/notifications`、`/public/activities`），前端降级后仍展示本地统计，真假难辨
4. 视觉上字号偏小（8–10px 共百余处）、圆角语言不统一，已完成第一轮令牌收敛

## 3. 目标功能：心晴活动闭环器

| 模块 | 需要什么 | 落在哪 | 后端依赖 |
|---|---|---|---|
| 1 快速搭建 | 模板数据 + 参数 | `/templates`、`/projects/new` | 无（静态数据） |
| 2 动态参与路径 | 心情入口 → 内容块映射 | `/p/:slug` 扩展 | 无 |
| 3 匿名便签 / 回声墙 | 匿名字段 + 本机存储 | `/p/:slug` | 无（本机） |
| 4 活动后回响卡 | 情绪词计数 + 规则 | `/p/:slug` 结束页、`/profile` | 无 |
| 5 下次衔接 | 高频词 → 模板映射 | `/projects/new` | 无 |
| 6 组织者看板 | 聚合查询 + 匿名阈值 | `/projects/:id/dashboard` | **需要** |

**结论：五个 MVP 里，四个可以纯前端先跑起来。**

## 4. 三个界面

**参与者（手机）**：四个入口（想放松 / 想表达 / 想认识人 / 想安静待着）→ 面板随选择变化 → 写一句 → 出回响卡。

**组织者（桌面）**：选主题 → 拿到可编辑的流程、物料清单、招募文案 → 活动结束后看情绪词与环节反馈 → 拿到下一场建议。

**回看（个人）**：只显示变化，不显示流水。例：「10 月说累了，12 月说想找人」。

## 5. 数据模型（前端可先落地）

```ts
// 匿名便签：不含 user_id，不关联任何人
ParticipantNote { activityId, text, mood, at }

// 个人档案：只存用户确认过的内容
ParticipantTrace {
  userId, activityId, semester,
  summary,        // 20 字摘要，用户可改
  openQuestion,   // 还没回答的问题
  change,         // 从 A 到 B
  promise,        // 答应过要做的事
}
```

**原则**：便签永远不进档案。只有他确认过的那句摘要才进。这样「匿名」和「个人回响卡」不打架。

## 6. 实施计划

### 第一期（纯前端，可见成果）

1. 6 套心理活动模板（破冰、压力释放、情绪表达、人际关系、自我探索、感恩练习），静态 JSON + 选择界面
2. 参与端四入口 + 面板切换
3. 匿名便签（`EchoNote`，已完成）+ 回响卡
4. 首页重排、转介待办重做、留白收紧

### 第二期

5. 个人档案页（变化时间线）
6. 活动后规则化反馈
7. 下次活动主题建议

### 第三期

8. 组织者看板（词云、环节反馈）
9. 跨设备聚合、风险词人工流程

## 7. 三条边界

1. **匿名分层**：系统实名、展示匿名；便签永不进档案
2. **不做诊断**：只做记录与引导；明确自伤表达时，弹求助卡（热线 12356、120/110），不自动通知任何人
3. **小样本保护**：少于 8 人、少于 10 条不出词云

## 8. 待定

- 匿名便签是否绑定账号（影响能否跨设备回看）
- 风险词触发后由谁值守、夜间如何处理
- 连续性接「同一个人」还是接「这一届」

# 修订 v2：真正的动态参与（覆盖 §3 第2行、§5、§6、§7）

## A. 偏差

原文把"动态参与"写成「4 个心情入口 → 固定内容块」，那是静态分支配置。真实机制是：

**用户自由输入 → 解析 → 更新个人状态标签与会话上下文 → 页面据此重渲染**

入口按钮只是降低门槛的快捷方式，任何时刻都开放文本输入；用户改主意，上下文重算，路径与提示随之变化。

## B. 数据模型（替换 §5）

```ts
type ActivityDomain = 'mental' | 'career'

interface ParticipantNote {
  activityId: string
  text: string
  mood?: string
  at: number
  candidateTraceId?: string // 用户勾选"存进我的轨迹"时才有的副本标记；原始便签仍匿名
}

interface ParticipantTrace {
  userId: string
  activityId: string
  domain: ActivityDomain
  semester: string
  summary: string
  openQuestion?: string
  change?: string
  promise?: string
  tags: Array<{ content: string; source: 'auto' | 'user'; createdAt: number }>
  sessionContext: {
    currentHint: string
    availablePaths: string[]
  }
}
```

- `tags` + `sessionContext` 是驱动源，不是流水笔记；每次输入都会更新
- **Trace 必须落后端**：只存本地就无法跨设备、跨活动读取，连续性直接失效
- 便签默认匿名不进档案；用户勾选后生成**私有副本**进 Trace，公开墙不受影响

## C. 动态回路

```
用户输入文本
  → 规则引擎（一期前端；三期换 agent）
  → 抽取标签，合并/覆盖 tags
  → 重算 sessionContext.availablePaths / currentHint
  → 页面读上下文重渲染面板与可选项
```

一期用关键词表即可，不需要大模型；但要**预留把 parse 换成 agent 的接口**：

```ts
parseTrace(input: { text: string; trace: ParticipantTrace }): Promise<Partial<ParticipantTrace>>
```

## D. 计划修订（替换 §6）

**一期**：6 套模板 → 参与端四入口 + 常驻输入框 → 前端规则引擎更新 Trace → 便签 + 回响卡（含"存进我的轨迹"勾选）→ **Trace 后端接口先行**，失败降级 local
**二期**：档案时间线、规则化反馈、跨活动读取历史 Trace 生成下一场建议
**三期**：组织者看板（k≥8）、agent 替换规则引擎、风险词人工流程

## E. 边界修订（替换 §7）

1. 便签默认不进档案；**用户主动勾选才生成私有副本**，公开墙保持匿名
2. 不做诊断，只记录与引导
3. 小样本保护：少于 8 人、少于 10 条不出词云

## F. 待定项结论

- 匿名：墙匿名、个人可自留，Trace 绑 userId
- 连续性：**优先接同一个人的 Trace**，其次才是整届统计
- 职规：同一个 Trace 模型加 `domain` 字段承载，不另起一套

# 实现记录：动态参与 v1（2026-11-17）

## 已落地

| 层 | 文件 | 说明 |
|---|---|---|
| 模型 | `web/src/types/trace.ts` | `ParticipantTrace`（tags + sessionContext）、`ParticipantNote`、`ActivityDomain`、`TraceParser` |
| 规则引擎 | `web/src/services/traceParser.ts` | 心理 / 职规两套关键词表；标签合并、提示重算、变化 / 未决问题 / 承诺抽取；只认明确自伤表达 |
| 轨迹存储 | `web/src/stores/trace.ts` | 本地优先，登录后尝试同步；写 `diy-campus:trace:v1:<userId>:<activityId>`；提供 `list / remove / clearAll / previousTrace` |
| 后端契约 | `web/src/services/traces.ts` | `GET /traces?activityId=`、`PUT /traces/:activityId`，未就绪时静默降级本地 |
| 参与面板 | `web/src/components/public/DynamicParticipation.vue` | 四个快捷入口 + 常驻输入框；标签可删；面板随输入重算；呼吸计时、清单、私密写作、求助入口 |
| 匿名便签 | `web/src/components/public/EchoNote.vue` | 新增「存进我的轨迹」勾选；默认仅本机，勾选后写私有副本 |
| 回看页 | `web/src/views/TraceTimelineView.vue` | `/trace`：只显示摘要、变化、未决问题；支持只看变化、单条删除、清空本机 |
| 活动页接入 | `web/src/views/PublicActivityView.vue` | 动态面板 + 便签；活动内容加载失败时面板仍可用，并明确提示 |

## 数据流

```
用户输入 / 快捷入口
  → parseTrace（关键词规则，一期）
  → 合并 tags、重算 sessionContext.availablePaths / currentHint
  → Panel 直接读 sessionContext 重渲染
  → Trace 写本地，登录时 PUT 后端（失败不阻塞）
```

## 连续性的两段落点

1. **同活动**：每次输入叠加标签，摘要按整条轨迹重算，不覆盖成只剩最后一句。
2. **跨活动**：`previousTrace()` 读同设备上最近一条其它活动轨迹，参与页开场显示「上次你留下过…」，可选「还在」或「变了」。

## 仍未完成（需要后端）

- `GET/PUT /traces` 接口尚未实现；实现后前端无需改动，登录态自动从本地切到同步。
- 跨设备回看、组织者聚合看板、风险词人工值守仍按原三期计划。
- 回响卡目前是面板内的「这次留下的」；独立回响卡页留在二期。
