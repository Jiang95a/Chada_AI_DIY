# 心屿同行 · 前端整体项目文档

> 版本：v1.0  
> 技术栈：Vue 3 + Vite + TypeScript + Pinia + Vue Router  
> 适用端：桌面浏览器 + 移动端 H5  
> 当前前端目录：`web/`

## 1. 项目概述

心屿同行是面向校园心理社团、班级心理委员和普通学生的心理活动组织平台。

核心目标不是做通用活动工具，而是让不熟悉前后端的心理社团成员能够：

- 快速发起一场心理活动
- 自动生成活动 H5 页面和分享海报
- 明确隐私边界与参与规则
- 发布活动并查看聚合参与数据
- 让学生以更安心的方式浏览、报名和反馈

## 2. 产品定位

一句话定位：

> 面向心理社团，安全、低门槛的心理活动组织平台。

产品重点关注：

- 活动整体流程
- 用户隐私保护
- 心理活动内容属性
- 减轻学生参与压力
- 心理知识科普与求助资源

产品不追求：

- 打卡签到
- 积分、排行榜
- 凑人数
- 把心理活动做成流量玩法

## 3. 明确不做清单

1. 不做心理诊断、心理测评打分、风险评估和精神状态判定。
2. 不做打卡、积分、排行榜、学时兑换。
3. 不做公开匿名树洞、自由匿名留言板。
4. 不把个人敏感信息和反馈原文送入大模型。
5. 不支持溯源匿名参与者。
6. 不承接线上心理咨询，危机情况只引导至学校心理中心。

## 4. 用户角色与权限

### 4.1 社团负责人

- 可以发布全校范围活动
- 审核普通干事提交的活动
- 查看本社团全部活动的聚合复盘数据
- 管理社团内普通干事账号
- 不能查看可定位个人的原始信息

### 4.2 社团普通干事

- 可以创建活动
- 不能直接发布全校活动
- 提交后等待负责人审核
- 只能查看、编辑和复盘自己创建的活动
- 无审核权限

### 4.3 班级心理委员

- 只能创建本班可见的班级活动
- 班级活动默认简化审核
- 只能查看本班活动的聚合统计

### 4.4 普通学生

- 浏览可参与的活动
- 报名
- 活动结束后提交反馈
- 不能查看后台统计和他人报名信息

### 4.5 隔离原则

活动带可见范围标签：

```text
全校
指定班级
```

角色决定是否能创建对应范围的活动，数据严格跟随活动隔离。

## 5. 核心业务流程

### 5.1 组织者流程

```text
发起活动
→ 填写核心信息
→ 填写活动详情与隐私规则
→ 生成 H5 活动页
→ 生成分享海报
→ 提交审核或直接发布
→ 分享活动
→ 查看聚合参与数据
```

### 5.2 学生流程

```text
浏览近期活动
→ 筛选活动类型
→ 查看活动介绍与隐私说明
→ 勾选知情同意
→ 匿名或实名报名
→ 收到活动链接与时间
→ 参与活动
→ 活动结束后匿名或实名反馈
```

### 5.3 审核流程

```text
普通干事提交 → 待审核
负责人查看 → 通过 / 驳回
驳回时必须填写原因
```

大型全校活动可选增加指导老师审核。

## 12. 隐私与匿名规则

### 12.1 匿名报名

- 不填写姓名、昵称
- 系统生成无意义匿名编号
- 匿名编号只用于单场活动内关联
- 活动归档后不再用于识别

### 12.2 知情同意

- 报名前必须勾选同意
- 展示保密边界、活动风险、退出权利、保存周期、数据使用范围

### 12.3 匿名反馈

- 反馈可以选择匿名化
- 组织者只能查看聚合结果

### 12.4 数据查看

- 组织者不能查看可定位个人的原始敏感信息
- 院系分布和时段分布只保留脱敏聚合数据

## 13. 活动创建规则

### 13.1 第一屏核心字段

- 活动名称
- 活动类型
- 活动时间
- 活动地点或线上链接
- 最大参与人数
- 是否匿名报名

### 13.2 后续字段

- 活动简介
- 参与须知

## 15. 海报生成

一期必须支持：

- 方形朋友圈分享海报
- 带二维码分享海报

二期再支持：

- 线下打印海报
- 长群发图

流程：

```text
填写活动信息
→ AI 生成初稿
→ 组织者二次编辑
→ 保存下载
```

## 16. AI 能力边界

AI 只用于：

- 生成活动 H5 页面初稿
- 生成海报
- 生成公开活动文案
- 检查隐私与文案表达

AI 不接触：

- 个人敏感信息
- 反馈原文
- 匿名参与身份
- 心理诊断相关内容

AI 失败时的兜底：

- 自动回落到通用心理活动模板
- 同时展示模板选择面板
- 允许组织者手动填写

## 17. 参与数据复盘

固定保留：

- 报名总人数
- 签到人数
- 报名到签到转化率
- 匿名报名占比
- 有效反馈数量
- 脱敏院系分布
- 报名时间段分布

不展示：

- 个体明细
- 排名
- 热度对比
- 打卡积分

## 18. 视觉设计规范

关键词：

```text
克制、可信、温暖
```

建议：

- 主色使用柔和低饱和颜色
- 背景使用白色、浅灰绿、暖米色
- 优先使用抽象底图和渐变
- 实拍照片必须取得授权
- 减少强刺激动画
- 活动卡片保持简洁，不猎奇

活动卡片必展示：

- 活动名称
- 活动类型标签
- 活动时间
- 地点或线上链接标识
- 报名状态

可选标签：

- 人数上限
- 匿名标识

## 21. 验收标准

1. 普通学生无需登录即可浏览公开活动。
2. 活动创建第一屏只展示核心必填字段。
3. AI 失败时仍能通过模板完成创建。
4. 匿名活动不要求填写姓名和昵称。
5. 未勾选知情同意不能提交报名。
6. 报名反馈支持匿名。
7. 组织者不能查看匿名个人身份。
8. 审核状态页面能展示待审核、已驳回和已通过。
9. 参与数据页只展示聚合数据。
10. 移动端 H5 页面在微信内可正常打开和报名。

## 22. 方案 B 前端接入状态

方案 B 新增三个能力已在前端按接口契约接入：

### 22.1 转介工单

- 公开活动页新增低调的“我希望有人联系我”勾选项和可选输入框。
- 提交只发送 `wantsContact / contact / preferredTime`，不携带活动回答。
- 组织者端新增 `/referrals` 转介待办页。
- 待办页支持待处理、已联系、已关闭三种状态。
- `pendingHours > 24` 的工单会标红提示超时。
- 状态接口只使用 `POST /referrals/{id}/status`。

### 22.2 个人成长档案

- 个人中心新增“我的参与轨迹”。
- 展示总场次、心理活动数、生涯活动数。
- 活动条目区分组织者、参与者、匿名参加。
- 匿名参加不展示任何活动回答内容。

### 22.3 生涯模板

- 模板类型新增 `kind: wellbeing | career | general`。
- 模板页和编辑器模板面板增加“全部 / 心理活动 / 生涯发展”分类。
- 模板读取逻辑改为按 `kind` 过滤，不再使用中文正则判断。

### 22.4 注意事项

方案 B 后端接口签名已固定，但当前代码分支尚未包含后端实现和 `009_career_and_referral.sql`。前端已按契约完成，联调前需确认后端代码和数据库迁移已进入同一分支。
