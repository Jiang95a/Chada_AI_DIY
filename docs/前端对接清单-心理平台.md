## 一、最高优先级：提交时带 consentId

### 现在是什么

`web/src/views/PublicActivityView.vue`：

```
190:  if (privacy.value.consentRequired && !consentAccepted.value) {   ← 只有前端拦一下
205:      await submitForm(slug.value, { pageId, formComponentId, answers })   ← 不传 consentId
```

`web/src/services/public.ts` 的 `submitForm` 也只发 `{ ...input, idempotencyKey }`。

**后果**：打开浏览器控制台直接 `fetch` 那个接口，不勾同意也能提交成功。所谓「匿名」和「知情同意」目前全是前端装饰。

### 改成什么

**第一步**：`web/src/services/public.ts` 的 `submitForm` 入参加一个可选字段

```ts
export async function submitForm(
  slug: string,
  input: {
    pageId: string
    formComponentId: string
    answers: Record<string, string | string[]>
    privacy?: { consentId?: string; anonymous?: boolean }   // ← 新增
  }
): Promise<{ submissionId: string; status: string }> {
  const idempotencyKey = crypto.randomUUID()
  return readData(
    await apiRequest(
      `/public/activities/${encodeURIComponent(slug)}/submissions`,
      {
        method: 'POST',
        body: JSON.stringify({ ...input, idempotencyKey }),
      },
      { auth: false }
    )
  )
}
```

**第二步**：`web/src/services/public.ts` 加两个新函数

```ts
/** 公开读取活动的参与说明与隐私档位（匿名可访问） */
export async function getPublicPrivacy(slug: string) {
  return readData<{
    privacyMode: 'real_name' | 'optional' | 'anonymous'
    consentRequired: boolean
    consentText: string
    retentionDays: number
    allowExport: boolean
    allowLeave: boolean
    quietSpace: boolean
  }>(await apiRequest(`/public/activities/${encodeURIComponent(slug)}/privacy`, {}, { auth: false }))
}

/** 勾选同意后换 consentId */
export async function recordConsent(slug: string, consentText?: string) {
  return readData<{ consentId: string; consentAt: string }>(
    await apiRequest(
      `/public/activities/${encodeURIComponent(slug)}/consents`,
      { method: 'POST', body: JSON.stringify({ consentText }) },
      { auth: false }
    )
  )
}
```

**第三步**：`PublicActivityView.vue` 的提交分支

```ts
if (action.type === 'submit') {
  if (privacy.value.consentRequired && !consentAccepted.value) {
    toast.pushToast('请先阅读并勾选参与说明', 'warn')

  }
  if (!validate()) { /* ...原样... */ }
```

### 后端已经保证的事

- 活动设成 `anonymous` 时，**即使你传 `anonymous: false`，服务端也按匿名存**，并生成 `anonymousToken`
- 活动开启 `consentRequired` 时，不带 `consentId` 会返回 **422**，`details.missing = ["consent"]`
- 说明文本改过之后，旧的 `consentId` 会失效，返回 422「参与说明已更新，请刷新页面重新阅读」——**这是故意的**，防止用户读到旧版说明就同意了

## 二、隐私面板：localStorage 改成后端

### 现在是什么

`web/src/composables/useActivityPrivacy.ts` 整个文件读写 `localStorage` 的 `diy-campus:activity-privacy:v1`。
`web/src/components/editor/PrivacySettingsPanel.vue:14,27` 的读写都走它。

**后果**：组织者把活动设成「匿名参与」，数据库里 `projects.privacy_mode` 还是默认的 `optional`；换台电脑打开，所有设置回默认值。**这个设置等于不存在。**

### 改成什么

后端接口：

```
GET  /projects/{projectId}/privacy   → PrivacySettings
PUT  /projects/{projectId}/privacy   ← PrivacySettings
```

`PrivacySettingsPanel.vue` 的 `save()` 改成：

```ts
async function save(): Promise<void> {
  try {
    await apiRequest(`/projects/${props.projectId}/privacy`, {
      method: 'PUT',
      body: JSON.stringify({
        privacyMode: form.privacyMode,
        consentRequired: form.consentRequired,
        consentText: form.consentText,
        retentionDays: form.retentionDays,
        allowExport: form.exportAllowed,      // ← 注意字段名不一致，见下
        allowLeave: form.allowLeave,
        quietSpace: form.quietSpace,
      }),
    })
    toast.pushToast('活动隐私与同意设置已保存', 'success')
  } catch {
    toast.pushToast('隐私设置保存失败', 'error')
  }
}
```

初次加载时用 `GET` 拿，不要再读 localStorage。

### ⚠️ 两个必须先对齐的问题

**问题 1：字段名不一致**

| 前端（`useActivityPrivacy.ts`） | 后端（`PrivacySettings`） |
|---|---|
| `exportAllowed` | **`allowExport`** |

**选一个，别两边都留着。** 你说用哪个，我这边配合改。

**问题 2：`retentionDays: 0` 会 422**

前端 `PrivacySettingsPanel.vue` 有一个选项是 `0`「长期保留（需有明确用途）」，后端约束是 `minimum: 1`、`maximum: 3650`。

要么前端把这个选项去掉/改成 3650，要么告诉我，我在后端放开。**从隐私角度我建议去掉。**

## 三、通知：写死数据换成真实数据

### 现在是什么

`web/src/components/studio/WorkspaceShell.vue`：

```
27:  const NOTIFICATION_READ_KEY = 'diy-campus:notifications-read:v1'
39:  const notifications = ref([
42:      { id: 'recruit-submissions', title: '社团招新季 收到 12 份新报名', ... }   ← 写死
51:      { id: 'vote-published', title: '摄影作品评选 已发布上线', ... }           ← 写死
57:  const unreadNotificationCount = ...
153: function openNotification(id) { ... }    ← 只在 localStorage 里记已读
162: function markAllNotificationsRead() { ... }
170: function persistNotificationReads() { ... }
```

**后果**：有人报名，组织者完全不知道。

### 改成什么

后端三个接口：

```
GET  /notifications              → { items: Notification[], unread: number }
POST /notifications/{id}/read    → { ok: true }
POST /notifications/read-all     → { updated: number }
```

`Notification` 结构：

```ts
{
  id: string
  type: string        // 例如 submission_received
  title: string
  body: string        // 正文不含参与者姓名/学号/匿名编号
  read: boolean
  createdAt: string
}
```

改法：

```ts
const notifications = ref<Notification[]>([])
const unreadNotificationCount = ref(0)

async function loadNotifications(): Promise<void> {
  try {
    const data = await readData<{ items: Notification[]; unread: number }>(
      await apiRequest('/notifications')
    )
    notifications.value = data.items
    unreadNotificationCount.value = data.unread
  } catch { /* 未登录或网络异常时静默失败 */ }
}

async function openNotification(id: string): Promise<void> {
  await apiRequest(`/notifications/${id}/read`, { method: 'POST' })
  await loadNotifications()
  showNotifications.value = false
}

async function markAllNotificationsRead(): Promise<void> {
  await apiRequest('/notifications/read-all', { method: 'POST' })
  await loadNotifications()
}
```

**`NOTIFICATION_READ_KEY` 和 `restoreReadNotifications`、`persistNotificationReads` 这三段可以整段删掉。**

`WorkspaceShell` 挂载时调一次 `loadNotifications()` 就行，不用轮询。
